# 종말예언 : 어둠탐사기록

원작 기반 2차 창작 괴담 문서 작성 사이트. 로그인 후 괴담 문서를 작성·열람하고, 추천/댓글로 반응할 수 있습니다. 로그인/데이터 저장은 Firebase(Authentication + Firestore)를 사용하며, 기존 "eye(응시)" 프로젝트와 같은 Firebase 프로젝트(`mumyeongchanrangyeo`)를 공유합니다.

## 파일 구성

- `index.html` / `login.html` / `register.html` / `write.html` / `view.html` — 페이지
- `style.css` — 전체 스타일
- `firebase-config.js` — Firebase 프로젝트 설정값
- `firebase-init.js` — Firebase 초기화 + 로그인/유저 프로필 관련 함수
- `docs.js` — 문서/추천/댓글 Firestore 함수
- `common.js` — 공용 상단 네비게이션, 익명 이름 표시 로직
- `sanitize.js` — 문서 본문 HTML sanitizer (저장/출력 시 허용된 서식만 통과)
- `firestore.rules` — Firebase 콘솔에 등록할 보안 규칙

## Firebase 콘솔에서 해야 할 설정 (최초 1회)

이 사이트는 `mumyeongchanrangyeo` 프로젝트를 그대로 재사용하므로, Firebase 콘솔에서 프로젝트를 새로 만들 필요는 없습니다. 다만 아래 항목은 확인/설정해주세요.

1. **Authentication 활성화**: Firebase 콘솔 → Authentication → Sign-in method에서 "이메일/비밀번호"가 켜져 있는지 확인하세요.
2. **Firestore 보안 규칙 반영**: Firestore Database → 규칙 탭에 이 저장소의 `firestore.rules` 내용을 그대로 붙여넣고 게시하세요. (이 사이트는 `users`, `counters`, `documents` 컬렉션만 사용하므로 eye 프로젝트가 다른 이름의 컬렉션을 쓰고 있다면 서로 영향을 주지 않습니다. 다만 규칙 파일 자체는 프로젝트당 하나이므로, eye 프로젝트에서 이미 다른 규칙을 쓰고 있다면 두 규칙을 하나의 파일로 합쳐서 게시해야 합니다.)
3. **승인된 도메인 등록**: Authentication → Settings → 승인된 도메인에 배포할 GitHub Pages 도메인(예: `아이디.github.io`)을 추가하세요. 등록하지 않으면 로그인이 막힙니다.
4. **관리자 계정 지정 (중요)**: 이 사이트에는 회원가입 화면에서 관리자를 지정하는 기능이 없습니다(보안상 의도적으로 뺐습니다). 본인 계정으로 먼저 회원가입한 뒤, Firestore Database → 데이터 탭 → `users` 컬렉션 → 본인 uid 문서를 찾아 `role` 필드 값을 `"user"`에서 `"admin"`으로 직접 수정하세요. 이 계정만 다른 이용자의 식별 번호(`이름 #12` 형태)를 볼 수 있고, 모든 문서/댓글을 삭제할 수 있습니다.

## 로컬에서 미리보기

정적 파일이라 별도 빌드는 필요 없지만, `file://`로 직접 열면 ES 모듈(import)이 막히는 브라우저가 있으므로 간단한 로컬 서버로 열어주세요.

```bash
cd gwaedam-site
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

## GitHub Pages 배포

1. GitHub에 새 저장소를 만들고 이 폴더의 파일을 모두 업로드(푸시)합니다.
2. 저장소 Settings → Pages → Source에서 배포할 브랜치(예: `main`)와 루트 폴더를 선택합니다.
3. 몇 분 후 `https://아이디.github.io/저장소이름/`으로 접속되면, 위 3번 항목(승인된 도메인)에 정확히 그 도메인을 등록했는지 다시 확인하세요.

## 기능 요약

- **회원가입/로그인**: 이메일 없이 "아이디(영문/숫자/-/_ 3~20자)"만 입력받습니다. 내부적으로는 Firebase Authentication의 이메일/비밀번호 로그인을 그대로 쓰되, `아이디@gwaedam.invalid`라는 실제로 존재하지 않는 가짜 이메일을 만들어 넘깁니다(`firebase-init.js`의 `usernameToEmail`). 가입 시 자동으로 순번 번호가 부여되지만, 이 번호는 관리자 계정에서만 보입니다.
- **문서 작성/수정**: 분류(백일몽 주식회사/초자연 재난관리국/무명찬란교), 식별 코드(선택), 제목, 본문. 본문 툴바로 굵게/기울임/취소선/붉은색/■검열 서식을 넣을 수 있습니다. 작성자 본인 또는 관리자만 수정·삭제할 수 있습니다.
- **문서 목록/상세**: 로그인한 사용자만 열람 가능. 상세 페이지에서 추천(1인 1회)과 댓글을 남길 수 있습니다.
- **익명화 정책**: 문서/댓글에 표시되는 작성자 이름은 항상 "이름"으로 통일되어, 일반 이용자는 서로를 구별할 수 없습니다. 관리자 계정으로 로그인했을 때만 "이름 #12"처럼 식별 번호가 함께 표시됩니다.

## 알려진 제약 / 다음 단계로 미룬 것

- 검열(■) 처리는 선택한 글자를 실제로 같은 길이의 ■ 문자로 치환하는 방식입니다. 되돌리려면 편집 화면에서 다시 타이핑해야 합니다(브라우저 자체 undo가 일부 동작할 수 있으나 100% 보장되지는 않습니다).
- **(수정됨) 굵게 서식이 게시 후 사라지던 버그**: 굵게/기울임 버튼이 `<span style="font-weight:bold">` 같은 인라인 스타일 형태로 서식을 만들었는데, 저장 시 sanitizer가 붉은색 외의 스타일은 전부 걸러내면서 굵게 표시가 통째로 사라졌습니다. 지금은 굵게/기울임/취소선이 `<b>`/`<i>`/`<s>` 같은 일반 태그로 만들어지도록 고쳐서 저장 후에도 유지됩니다. 다만 **이 수정 전에 이미 게시한 문서**는 저장된 시점에 이미 굵게 표시가 빠진 채로 저장되어 있으므로, 해당 문서를 열어 다시 굵게 지정하고 저장해야 복구됩니다.
- **비밀번호를 잊어버린 경우**: 아이디만 받는 방식이라 Firebase의 "이메일로 비밀번호 재설정" 기능을 쓸 수 없습니다. Firebase 콘솔의 Authentication → Users 목록에도 비밀번호를 직접 새 값으로 바꿔주는 버튼은 없어서(콘솔 UI로는 계정 비활성화/삭제만 가능), 지금 구조에서 현실적인 방법은 해당 계정을 삭제하고 새 아이디로 다시 가입하는 것뿐입니다. 관리자가 직접 비밀번호를 재설정해주고 싶다면 Firebase Admin SDK를 쓰는 별도의 작은 관리 도구를 추가로 만들어야 합니다(이번 범위에는 포함하지 않았습니다).
- 프로필 사진, 닉네임 커스터마이징, 문서 검색/태그, 관리자 전용 검수(승인) 워크플로우는 이번 범위에서 제외했습니다. 필요하시면 이어서 추가할 수 있습니다.
- Firestore 보안 규칙은 소규모 팬 프로젝트 기준으로 단순화했습니다. 이용자가 크게 늘어나면 유저 번호 발급 카운터의 동시성, 관리자 권한 부여 방식 등을 더 엄격하게 다듬는 것을 권장합니다.
